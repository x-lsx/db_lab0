# Лабораторная работа: импорт данных из SQLite в PostgreSQL и экспорт отчёта в Excel

## Описание проекта

Данный проект реализует задачу входного контроля по теме "импорт данных из ненормализованной структуры в нормализованную БД и последующий экспорт выборки в документ электронных таблиц".

В качестве предметной области выбрана область видеоигр. Исходные данные хранятся в SQLite в денормализованной таблице, затем они преобразуются в JSON, загружаются в нормализованную схему PostgreSQL и используются для формирования аналитического отчёта в формате Excel.

## Цель

Реализовать полный цикл обработки данных:

1. чтение данных из ненормализованной базы SQLite;
2. преобразование и промежуточное хранение в JSON;
3. загрузку в нормализованную БД PostgreSQL;
4. формирование аналитического отчёта;
5. экспорт результатов в документ Excel.

## Архитектура решения

### 1. Источник данных: SQLite

Ненормализованная база данных хранится в файле `games.db` и содержит таблицу `games_1nf`.

Эта таблица объединяет данные о:
- играх;
- жанрах;
- компаниях;
- странах;
- платформах;
- разработчиках;
- церемониях награждения;
- режимах игры;
- языках интерфейса.

### 2. Промежуточный формат: JSON

Скрипт `read_sqlite.py` читает данные из SQLite и сохраняет их в файл `games.json`.

Это позволяет:
- сделать перенос данных между системами более простым;
- сохранить исходный набор данных в удобном промежуточном формате;
- обеспечить независимость между этапами загрузки и экспорта.

### 3. Нормализованная база данных: PostgreSQL

Схема базы данных создаётся скриптом `init_schema.sql`.

В проекте используется нормализованная схема с несколькими таблицами и связями:
- `countries`;
- `companies`;
- `genres`;
- `games`;
- `platforms`;
- `game_platforms`;
- `main_developers`;
- `game_developers`;
- `ceremonies`;
- `game_ceremonies`;
- `languages`;
- `game_languages`;
- `game_modes`;
- `modes_in_game`.

Такая структура соответствует требованиям лабораторной работы по нормализации данных и поддерживает связи типа 1:N и M:N.

### 4. Загрузка данных

Скрипт `pg_loader.py` выполняет следующую последовательность действий:
- читает данные из `games.json`;
- выделяет справочники и связанные сущности;
- формирует наборы значений для вставки;
- загружает данные в PostgreSQL через `psycopg2`;
- использует `ON CONFLICT DO NOTHING` для защиты от дублирования.

### 5. Генерация отчёта Excel

Скрипт `excel_report.py` формирует запрос к PostgreSQL и подготавливает набор данных для отчёта.

Далее вызывается отдельный генератор `excel_generator.py`, который:
- получает JSON-данные;
- создаёт документ Excel;
- заполняет заголовки и строки;
- сохраняет итоговый файл в формате `.xlsx`.

В результате создаётся файл `Top_Studios_Report.xlsx`.

## Список файлов

- `main.py` — основной запускной файл проекта;
- `read_sqlite.py` — чтение данных из SQLite и сохранение в JSON;
- `pg_loader.py` — загрузка данных в PostgreSQL;
- `init_schema.sql` — SQL-скрипт создания нормализованной схемы;
- `excel_report.py` — формирование выборки и вызов экспорта в Excel;
- `excel_generator.py` — генерация Excel-файла из JSON;
- `games.db` — исходная SQLite-база данных;
- `games.json` — промежуточный JSON-экспорт данных;
- `Top_Studios_Report.xlsx` — результирующий Excel-отчёт;
- `requirements.txt` — список зависимостей проекта.

## Требования

Для корректной работы проекта необходимы:

- Python 3.10+
- PostgreSQL, запущенный локально на `localhost:5432`
- установленная библиотека `psycopg2`
- библиотека `openpyxl`

## Установка зависимостей

```bash
pip install -r requirements.txt
```

## Настройка подключения к PostgreSQL

В файле `main.py` задаются параметры подключения:

```python
 db_config = {
    "dbname": "games_db",
    "user": "artur",
    "password": "artursubd",
    "host": "localhost",
    "port": "5432"
 }
```

Перед запуском необходимо убедиться, что в PostgreSQL существует база данных `games_db` и пользователь имеет доступ к ней.

## Запуск проекта

Запуск выполняется через основной файл:

```bash
python main.py
```

После запуска программа делает следующее:

1. читает данные из `games.db`;
2. сохраняет их в `games.json`;
3. создает/обновляет схему в PostgreSQL;
4. загружает данные в нормализованную БД;
5. генерирует Excel-отчёт.

## Пример результата

В результате работы строится отчёт, содержащий показатели по компаниям, например:
- название компании;
- страна;
- количество игр;
- средний рейтинг;
- лучшая игра компании.

## Краткое описание бизнес-логики

Проект моделирует процесс работы с данными игрового портала:
- исходная таблица содержит смешанные атрибуты и повторяющиеся значения;
- после нормализации данные распределяются по отдельным сущностям и таблицам;
- аналитик может быстро получать выборки и формировать отчёты по компаниям и играм.
